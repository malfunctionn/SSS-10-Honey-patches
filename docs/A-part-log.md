## 1. 담당 범위

A 파트는 공격 세션의 **메모리 상태를 저장하고, 다른 사용자의 민감정보를 가짜 값으로 치환한 뒤, 미끼 서버에서 복원하는 기능**을 담당한다. 실제 프로세스 메모리 복제 대신 Python 객체와 JSON 스냅샷을 사용하는 축소 구현이다.

| 파일 | 역할 | 상태 |
|---|---|---|
| `hpsim/config.py` | 명세의 상수와 설정 | 완료 |
| `hpsim/memory.py` | `Record`·`Heap`·`Session`, Redaction, 스냅샷 변환 | 완료 |
| `hpsim/honeypatch.py` | 세션 초기화, Checkpoint, Fork, Terminate, Restore | 완료 |
| `tests/test_memory.py` | 메모리·치환 정책·스냅샷 검증 | 통과 |
| `tests/test_fork.py` | 실제 target/decoy 서버를 이용한 M3 검증 | 통과 |

**협업 경계:** B는 서버·프로세스, C는 프록시, D는 시나리오 실행·결과 취합을 담당한다. A는 공개 API를 유지하고 A 코드와 관련된 통합 오류를 확인한다.

## 2. 구현 내용

### 메모리와 Redaction

- 16바이트 세션 버퍼와 H0~H4 힙 레코드를 모델링한다.
- `sensitive`와 `freed` 속성으로 민감정보 및 해제 메모리를 구분한다.
- `redact=on`은 공격자 이외의 민감 레코드를 해제 여부와 관계없이 치환한다.
- `redact=nofreed`는 해제된 레코드를 제외하고, `off`는 치환하지 않는다.
- 원본 힙과 공격자 자신의 세션 토큰은 유지한다.

### Checkpoint → Fork → Restore

1. 패치 조건에 걸린 요청에서 미끼 확보를 요청한다.
2. 요청 처리 직전의 세션·힙 상태를 스냅샷으로 만든다.
3. 다른 사용자의 등록된 민감정보를 치환하고 미끼 서버에 전달한다.
4. 복원에 성공하면 target의 공격 세션을 종료한다.
5. 미끼 서버는 복원된 상태에서 같은 요청을 다시 처리한다.

미끼 확보·복원에 실패하면 target 상태를 유지하고 일반 패치의 거부 동작으로 돌아간다. 실제 TCP 연결 전환은 C 파트의 책임이다.

## 4. 원논문과 구현의 차이

| 구분 | 원논문 | 이번 구현 |
|---|---|---|
| 상태 복제 | CRIU 기반 프로세스 체크포인트·복원 | 세션과 모델 힙을 JSON 스냅샷으로 전달 |
| 비밀정보 제거 | 실제 프로세스 메모리의 비밀 제거 | `sensitive`로 등록한 레코드만 치환 |
| 실행 흐름 | 실행 상태 이전·재개 | 복원된 상태에서 같은 요청 재전송 |
| 미끼 격리 | 컨테이너 기반 격리 | 로컬 프로세스 기반 시뮬레이션 |

명세의 고정 시드로 가짜 값을 만들기 때문에 실행 결과를 재현하기 쉽지만, 실제 운영 환경의 예측 불가능성을 제공하지는 않는다. **모델에 등록되지 않은 비밀정보까지 보호한다고 주장하지 않는다.**

## 5. 13주차 — A 반례 검증 (C01~C04, C21)

**작업 파일:** `tests/test_cx_memory.py` (신규, A 담당)

| ID | 검증 내용과 사전 기대값 | A 단위 테스트 관찰 | 분류 (잠정) |
|---|---|---|---|
| C01 | `nofreed`: 3건 치환·2건 노출 / `on`: 5건 치환·노출 0 | 일치 | **반례 아님**. `nofreed`는 해제된 비밀을 보호하지 않는 선택지 |
| C02 | 공개 시드로 H1 가짜 값을 독립 계산하고 미끼 응답과 대조 | 일치. 같은 값 반복 생성 | **SCOPE**. 공개·고정 시드로 예측 가능 |

**C02 상세:** 구현의 공개 `SEED`와 `H1` ID로 SHA-256을 계산하면 `tok_a9bd82d091d5d37e`가 나오고, 공격 응답의 **24~43바이트**와 일치한다. 예측 가능한 가짜 데이터가 구별 단서가 될 수 있다는 한계다. 단, 실제 공격자의 판별 성공률을 측정한 것은 아니다. v1.5 명세 11.4절 C02의 “H1 64~83바이트”는 **명세 내부 표기 오류**다. H1은 24~43바이트, 64~83바이트는 H3이다. 명세 담당자에게 정정 요청이 필요하며 기존 입력·기대 결과를 임의로 수정하지 않는다.
