# HoneyPatch 시뮬레이터 · 12주차 B 파트 작업 요약

- **프로세스 관리** — 자식 프로세스의 기동 신호(READY)를 확인하고, 기동 실패나 부모 종료 시 자식을 정리하도록 구현했다.
- **백엔드 서버** — target·decoy의 세션 조회, heartbeat 요청 처리, 상태 조회·복원·종료 API를 구현했다.
- **미끼 풀** — 번호가 가장 작은 미끼를 배정하고, 반납 시 프로세스를 종료해 `recycling` 상태로 유지하도록 구현했다.
- **명세 반영** — 미지원 HTTP 메서드는 `404`, 형식이 잘못된 heartbeat는 `400`과 `application/octet-stream`을 반환하도록 수정했다. 복원 테스트에는 필수 필드 누락 시 기존 상태가 유지되는지 확인하는 항목을 추가했다.
- **검증 현황** — 실제 자식 프로세스로 기동·종료와 풀 반납을 확인했다. A 모듈 대역으로 세 모드의 HTTP 응답을 확인했다. Windows 루프백 접속 제한으로 전체 소켓 테스트는 중단됐으며, 실제 A·C 모듈과의 통합 검증은 남아 있다.

## AI 활용 방식

AI 코딩 도구인 Codex에 `SPEC.md` v1.4.1을 읽고 부록 A의 B 담당 범위만 구현하도록 요청했다. AI는 명세의 공개 API와 모듈 경계를 기준으로 `proc.py`, `server.py`, `pool.py` 및 관련 테스트 코드를 작성했다. 풀은 12주차 M4 범위에 맞춰 반납 시 프로세스를 종료하고 `recycling` 상태로 남기도록 구현했으며, M6의 자동 재생성은 포함하지 않았다.

구현 후에는 사용자가 검토한 문제점을 AI에 전달해 수정을 진행했다. 특히 잘못된 최초 heartbeat 요청에서도 세션과 힙 레코드가 생성되는 문제를 지적했고, AI가 입력 검증을 세션 생성보다 먼저 수행하도록 수정하고 상태 변경 여부를 확인하는 회귀 테스트를 추가했다. 내부 API의 접근 제한, 미구현 M6 기능, 통합 테스트의 한계도 검토 내용에 따라 문서에 명시했다.

검증 과정에서는 AI가 실제 자식 프로세스와 HTTP 요청을 사용하는 스모크 테스트를 작성하고 실행했다. 당시 A 담당 모듈이 없어 테스트용 대역으로 인터페이스를 모사했으므로, 이 결과는 실제 A의 `hp_fork()` 성공·실패 처리나 C의 프록시 라우팅 전환을 검증한 결과와 구분했다. Python 3.9 문법 호환성도 검사했으며, pytest 전체 실행과 macOS 검증은 완료한 것으로 간주하지 않았다.

코드 외에는 불필요한 파일을 제외하는 로컬 Git 설정, 원본 명세와의 중복 확인, 새 문서의 `docs/` 이동에 AI를 활용했다. `proc.py`의 주석은 사용자가 지정한 방식에 따라 바깥 함수 위에 처리 흐름과 입력·출력을 설명하도록 정리했다. 구현 범위와 수정 방향은 사용자가 지정하고, AI는 코드 작성·수정·검증 및 문서 정리를 수행하는 보조 도구로 활용했다.
